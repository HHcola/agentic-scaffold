# 角色目录

| 文件 | 职责 |
| --- | --- |
| [`ORCHESTRATION.md`](ORCHESTRATION.md) | 编排、交接、状态推进与完成标准 |
| [`shared/PRINCIPLES.md`](shared/PRINCIPLES.md) | 所有角色共同遵守的工程原则 |
| [`roles/orchestrator.md`](roles/orchestrator.md) | 问题定义、路径选择、任务协调 |
| [`roles/product.md`](roles/product.md) | 需求、范围、验收与优先级 |
| [`roles/architect.md`](roles/architect.md) | 系统设计、权衡、风险与测试策略 |
| [`roles/developer.md`](roles/developer.md) | 实现、自动化测试与技术证据 |
| [`roles/reviewer.md`](roles/reviewer.md) | 代码质量、安全和可维护性评审 |
| [`roles/qa.md`](roles/qa.md) | 独立验证、回归与缺陷报告 |
| [`roles/release.md`](roles/release.md) | 发布、回滚、监控与运行交接 |

角色可以映射为不同 Agent，也可以由同一个 Agent 顺序扮演。关键是保持每个角色的输入、判断标准和输出独立。
