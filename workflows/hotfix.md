# Bug 与紧急修复

## 常规 Bug

1. 通过最小复现确认期望与实际。
2. 记录影响范围、严重程度和环境。
3. 创建 `bug` 类型任务。
4. 实施最小修复与回归测试。
5. 独立评审、验证后发布。

## 紧急修复

紧急不等于无证据。可以缩减 Discovery/Design 的文档深度，但要保留：

- 事故现象与用户影响。
- 最小复现或诊断依据。
- 修复为何最小且安全。
- 实际执行的验证。
- 发布与回滚路径。
- 事后补做的根因分析和长期修复任务。

若必须跳转状态，使用 `--force` 并在任务日志记录批准人和风险：

```bash
agentic-scaffold task move TASK-YYYYMMDD-NNN REVIEW --force \
  --note "事故 INC-123 紧急修复；批准人 @oncall；已执行最小回归"
```

## Hotfix 完成条件

- 当前故障症状已消失或有可观测证据。
- 修复没有扩大故障面。
- 回滚路径可用。
- 后续根因分析与防复发事项已创建。
